Performance Optimization

Estratégias para maximizar performance com IA local em hardware limitado (16GB VRAM, 32GB RAM).

Lazy Knowledge Loading

Problema: Carregar 172 knowledge files desperdiça tokens e lentifica inference.

Solução: INDEX.json com 172 arquivos indexados por keywords, domínio, categoria.

1. Ler INDEX.json (~2.6k linhas, mas só keywords/summaries)
2. Buscar por keywords da tarefa
3. Carregar APENAS resumo dos 2-3 arquivos mais relevantes
4. Se resumo é suficiente → não carregar arquivo completo
5. Se precisa de mais → Read(filePath, limit=100)

Checkpoint & Resume (Tarefas Ilimitadas)

Problema: Tarefa excede contexto mesmo após compactação → agente para.

Solução: Salva checkpoint → nova sessão → retoma de onde parou.

Sessão 1: Cria entidades, services (60%) → checkpoint
Sessão 2: Cria validações, testes (90%) → checkpoint
Sessão 3: Cria docs, quality gates (100%) → completo ✅

Checkpoint contém: steps completados, step atual, steps restantes, arquivos criados/modificados, decisões tomadas.

Arquivo: .xforge/checkpoints/<task-id>.json

Limite: Máximo 10 retomadas por tarefa.

Adaptive Eviction (Limiares Adaptativos)

Problema: Limiares fixos (32k) não funcionam com 128k context.

Solução: Limiares baseados em % do contexto real — adapta automaticamente.

O Loop Autônomo

LOOP FOREVER:
1. Escolher ideia de experimento
2. Implementar mudança
3. Commit
4. Rodar score.ps1 → medir xfs
5. SE melhorou → KEEP (avançar branch)
6. SE piorou → DISCARD (revert + analisar)
7. SE crash → tentar fix (máx 3) → senão discard
8. Repetir
NEVER STOP até humano interromper

Métrica Única: XForge Score (xfs)

DimensãoPesoO que mede
Correctness30%Testes passam? Build limpo? Sem erros?
Performance20%Sem N+1, sem sync-over-async, sem memory leaks
Quality20%Formatação, warnings, padrões
Simplicity15%Mudança mínima, poucos arquivos, sem novas deps
Prevention15%Erros prevenidos, padrões aplicados

⚠️ Scoring Imutável

O agente NUNCA pode modificar o sistema de pontuação. O script score.ps1 é read-only. Os resultados em results.tsv são append-only. A única exceção é solicitação humana explícita.

Simplicity Criterion

"All else being equal, simpler is better."

Ganho xfsComplexidadeDecisão
> 5%Baixa✅ KEEP
> 5%Alta⚠️ REVIEW
1-5%Média⚠️ REVIEW
< 1%Alta❌ DISCARD

Fórmula: vale_a_pena = (ganho × 100) / (complexidade × 10) — Se > 1.0: KEEP

  • Confirmar resultado SÓ DEPOIS de completar

Modo Offline — Split Architecture

Otimizado para hardware local: 16GB VRAM, 32GB RAM, Ryzen 7 5700G. Dois modelos rodam em paralelo para máxima eficiência.

Router (Classificador)

Modelo: Detectado automaticamente

Detecção: gemma, qwen2.5:7b, phi3, llama3:8b

Função: Classifica intenção, seleciona skill, escolhe knowledge

Worker (Execução)

Modelo: Detectado automaticamente

Detecção: qwen3-coder, qwen2.5:72b, deepseek-coder

Função: Geração de código, raciocínio complexo, multi-file

Worker (Execução)

Modelo: qwen2.5:72b (Q4_K_M)

Contexto: 32k tokens

VRAM: ~10GB + 22GB RAM

GPU Offload: ~35% das camadas

Geração de código, raciocínio complexo, multi-file

Detecção Automática de Modelos

Não precisa de modelos específicos — o sistema detecta automaticamente qual modelo serve para cada papel:

PapelPadrão de DetecçãoUso
Routergemma, qwen2.5:7b, phi3, llama3:8bClassificação rápida
Workerqwen3-coder, qwen2.5:72b, deepseek-coderCódigo complexo
Fallbackqwen3.6, qwen2.5:14b, llama3:70b, mixtralTarefas médias
Embednomic-embed, embedRAG e busca

O xforge-init detecta e mostra qual modelo foi atribuído a cada papel.

Context Budget (32k padrão)

Por que 32k e não 128k? CPU inference com 128k é 3-4x mais lento. Para 90% das tarefas, 32k é suficiente.

Eviction automática:

  • 80% (25.6k): Comprime histórico anterior a 3 turns
  • 90% (28.8k): Remove knowledge files não referenciados
  • 95% (30.4k): Trunca outputs de ferramentas > 300 linhas
  • 98% (31.4k): Compacta tudo — mantém apenas contexto da tarefa atual

Perguntas Frequentes (FAQ)

Preciso de internet para usar?

Não. O sistema é 100% local via Ollama. Só precisa de internet para: uploads, webfetch, e updates do knowledge.

Qual hardware mínimo recomendado?

GPU 16GB VRAM + 32GB RAM + CPU 8 cores. Funciona em CPU-only mas é 3-4x mais lento.

O sistema é tudo local?

Sim. O XForge é otimizado para Ollama (100% local, gratuito, offline). O sistema detecta automaticamente os modelos instalados e adapta o comportamento.

Como adicionar um novo skill?

Crie .kilo/skills/minha-skill/SKILL.md com frontmatter (name, description) + corpo com procedimento. Rode doctor.ps1 para validar.

O agente pode modificar o sistema de pontuação?

Não. O scoring é imutável. A única exceção é solicitação humana explícita.

Como funciona a memória entre sessões?

Preferências ficam em .xforge/memory/. O agente lembra: decisões tomadas, padrões aprendidos, preferências do usuário.

Posso rodar múltiplos agentes em paralelo?

Sim. O Multi-Agent Orchestration coordena até 2 workers simultâneos (16GB VRAM). Tarefas complexas são divididas entre agentes especializados.

E se a tarefa for maior que o contexto?

O sistema usa Checkpoint & Resume: salva o progresso em .xforge/checkpoints/ e continua na próxima sessão. Máximo 10 retomadas por tarefa. Não precisa preocupar — tarefas grandes funcionam automaticamente.

Como atualizar o knowledge base?

Rode .\.kilo\automation\scripts\check-updates.ps1. Ele verifica 28 fontes oficiais e alerta sobre tabelas expiradas.
